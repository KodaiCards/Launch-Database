# Projection Wave — Auditor A (Broad Fresh-Eyes)

## Stack snapshot

Three distinct projection surfaces exist: (1) `buildPscRusProjection` in `automation.js` — 90-day forward-looking pace forecast for all RUS-program work, grouped by engineering-contract umbrella with per-job-bucket breakdowns; (2) `buildInspectionRevenueProjection` in `automation.js` — inspection-only subset with weighted-recency hourly pace model, callable but no longer routed (legacy `inspection-projection` alias now routes to `buildPscRusProjection`); (3) `projected_revenue` static column on `projects` — a manually-set or footage-backfilled integer, summed by `/api/revenue/projected-total`. The dashboard `loadInspectionProjection()` function is a hard no-op (`return;` line 1). All three surfaces have explicit "retired pending revisit" markers in the HTML; the tile renders `UNDER CONSTRUCTION`. The project-drilldown tiles (×2) are hardcoded UNDER CONSTRUCTION in `admin.html` JS render.

## Negative findings (confirmed clean)

- **Double-counting via rollup containers:** `/api/revenue/projected-total` correctly uses `NOT EXISTS (SELECT 1 FROM projects c WHERE c.parent_id = p.id)` — rollup containers are excluded from the projected total sum. Verified in revenue.js projected-total query.
- **Auth gates:** `/api/revenue/projected-total`, `/api/automation/psc-rus-projection`, `/api/automation/inspection-projection` all require `requireManagerOrAdmin` or `requireAdmin`. `requireAdmin` on the projection endpoints is correct. Verified in routes/revenue.js and automation.js installAutomationRoutes.
- **SQL injection:** All projection queries use parameterized `$1`/`$2` placeholders with the `pool.query(sql, params)` pattern. No user input is interpolated into SQL strings in any projection path. Verified across all five queries in buildPscRusProjection.
- **Rollup double-counting in PSC RUS projection:** `buildPscRusProjection` filters `COALESCE(p.is_rollup, FALSE) = FALSE` — only leaf projects enter the umbrella bucketing. Verified in automation.js PSC RUS project query.
- **Budget cap:** When a budget is set, the umbrella-level projection is capped at `budget_remaining = max(0, budget_allocated - billed_to_date)`. The `will_exhaust_budget` flag is correctly set when `paceHours >= budgetHours`. Math verified in buildPscRusProjection step 7.
- **Footage projects excluded from hourly pace:** `buildPscRusProjection` uses the `jobBucket` function to route permitting projects to the `permitting` bucket which uses a different formula (expected minus billed), not hourly pace. Hourly pace is only applied to `inspection` and `re` buckets. Verified in automation.js bucketKey branching.
- **revenue.js billing_type gate:** monthly-summary and by-client CTEs both gate `earned` on `billing_type = 'hourly'` for hourly calculation and use `expected_revenue` for footage completed projects. The previous bug (hours × rate for footage projects) is already fixed in the current code with comments noting the fix. Verified in revenue.js lines 20–90.

## Coverage gaps

- **`invoice_generator.js` projected_revenue usage:** The invoice generator does not reference `projected_revenue` at all — it uses `actual_hours × billing_rate` from `time_entries` for each billing period. No gap found there relative to projection scope.
- **`routes/_helpers.js` `calcProjectFinancials`:** Only called at project-creation time to compute `expected_hours`/`expected_revenue`; does not feed into runtime projection math directly. Reviewed for completeness; no findings in scope.
- **`admin.html` lines 705, 771, 6350 exact line numbers:** Confirmed all three UNDER CONSTRUCTION locations found via pattern search. Could not confirm exact line numbers without a line-numbered file read, but content match is solid.
- **Scheduler invocations of projection functions:** `startScheduler` in `automation.js` does NOT call either projection function — it only calls `buildDigest`, `findStalePermits`, `findBudgetBurn`, and `runAuditCleanup`. Projection endpoints are purely on-demand. No caching or pre-computation occurs.
- **`buildMonthlyBillingDraft`:** Reviewed briefly — outside projection scope proper. Uses `period_hours × billing_rate` not `projected_revenue`. No cross-contamination with projection logic.
