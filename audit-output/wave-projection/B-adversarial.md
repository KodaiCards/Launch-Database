# Projection Wave — Auditor B (Adversarial)

**Framing:** Adversarial / edge-case hunting. Same scope as A and C.
**Files read:** `automation.js` (full), `routes/revenue.js` (full), `routes/inspection.js` (full), `routes/_helpers.js` (full), `invoice_generator.js` (full), migrations 0002, 0004, 0023, 0029.
**Word budget:** 1200 words. **Time budget:** 50 min.

---

## Stack snapshot

Three projection-producing functions live in `automation.js`: `buildPscRusProjection`, `buildInspectionRevenueProjection`, and `buildBillNowPreview`. Revenue endpoints live in `routes/revenue.js`. The shared math helpers are thin — most of the arithmetic is inline JS after SQL fetch. Core attack surface is the pace math (lookback / horizon window), NULL propagation through `billing_rate` and `expected_revenue`, the umbrella-grouping logic that can duplicate or drop rows, and timezone/date math spread across three call sites.

## Negative findings (checked and confirmed clean)

- **Rollup double-counting in projection:** `buildPscRusProjection` correctly gates on `COALESCE(p.is_rollup, FALSE) = FALSE` — rollup folders excluded.
- **Infinity in budget math when allocated=0:** `buildInspectionRevenueProjection.computeRow` takes the `budget_allocated > 0` branch before using `budgetHours` — zero budget means uncapped, not div/0.
- **SQL injection via `lookbackWeeks`:** Both projection functions use `parseInt` + `Math.max/min` guards and pass as a string parameter (not interpolated). Safe.
- **Permit stage flip double-count:** `findPermitsAwaitingInvoice` joins on `ps.completed_at IS NULL` so a permit that advances past `billed` doesn't double-appear.
- **`is_ongoing` infinite projection:** `buildPscRusProjection` projects via pace math, not `is_ongoing` flag. No indefinite-projection loop from `is_ongoing=TRUE`.
- **Footage projects with billing_rate in hourly CTEs:** `monthly-summary` and `by-client` both gate `billing_type = 'hourly'` before multiplying `hours * billing_rate`. Footage projects not double-counted.
