# Wave 3 FE-A11y — Auditor B: UX-Flow / Daily-Workflow

**Stack snapshot:** Six portals audited through the lens of five user personas: keyboard-only operator, screen-reader user (NVDA/JAWS/VoiceOver), low-vision (200% zoom), color-blind, and time-pressured. Five daily workflows walked mentally: admin project create/edit/close; permitter advancing permit stage; designer doc upload; manager table navigation; splice contractor grid. Focus, ARIA announcements, and keyboard reachability were the primary axes. ≤80 words.

## Negative Findings (confirmed clean)

- All 34 static `.modal-overlay` divs in admin/permitting/design/timeclock have `role="dialog"`, `aria-modal`, `aria-labelledby`, and `aria-label="Close dialog"` on close buttons. Temp-Claude wave landed correctly.
- `overlay_modal.js` (shared utility modals): full Tab trap, focus return, ESC. Fully compliant.
- `dialog.js` (`confirmDialog`/`alertDialog`): role, modal, labelledby, ESC, click-outside, initial focus. Compliant.
- `login.html`: both inputs have `<label for=>`, error region has `role="alert"` + `aria-live="assertive"`.
- Admin nav tablist: `role="tablist"`, each tab has `role="tab"` + `aria-selected` + `aria-controls`, `showView()` toggles `aria-selected`. Keyboard navigation works.
- Skip-nav links present in all portals. Focus rings not removed globally (`outline:none` only on MapLibre canvas container, which is not a user-focusable control).
- Status badges (`statusBadge()` function) include text labels — status is not conveyed by color alone.
- `toast.js` close button has `aria-label="Dismiss"`. Toast messages are readable text.
- `change_password_modal.js`: focus moves to first input on open (line 58, with 50ms setTimeout). This single positive behavior noted; rest of the modal is non-compliant (see finding #4).
- Permitting nav tabs (`#tab-pipeline`, `#tab-potential`) already have `role="tab"` + `aria-selected` with correct `sv()` updates — only the settings sub-tabs inside the modal are missing this (finding #6).
