# Wave 1.5 Auditor B — Adversarial / Subtle

**Stack snapshot:** Express + pg-pool + Puppeteer + JWT/cookie auth. Audit focused on race conditions, TOCTOU gaps, channel-pinning, edge-case NULL/0 boundaries, privilege confusion, and audit-trail forgery across eight scope items. Most subtle risk is the `{}` mw pass to `potential_permits` and `inspection` that silently converts `requireAuth()` into a no-op.

## Negative findings (confirmed clean)

- `actorOf` in `portal_module.js`: the `req.body.proposed_by` fallback only fires when `req.user` is falsy — meaning `requireAuth` already passed. Not exploitable for spoofing in auth-gated routes.
- `time_entries` FK: `ON DELETE RESTRICT` (not CASCADE). Users cannot delete their own audit trail by deleting a project. Confirmed clean.
- All user FK references (`REFERENCES users(id)`) use `ON DELETE SET NULL`, not CASCADE. No cascade-delete audit-trail forgery path.
- `potential_permits.js` body-actor fix: `submitted_by` and `reviewed_by` are derived from `req.user` (lines 36, 54). The fix is correct where `requireAuth` actually fires — the bug is that it doesn't fire (B-1).
- SSE `sseTokenIatSec` captured at connect time (`req.user.iat`) and compared against DB `tokens_invalid_after` each tick. Correct TOCTOU behavior when the DB query succeeds.
- JWT verify uses `algorithms: ['HS256']` explicitly — algorithm confusion (`none` / RS256 downgrade) is blocked.
- Splice Puppeteer renders (`splice.js:2630`, `3650`) use `page.setContent` (not `page.goto`) with server-generated HTML. SSRF surface is smaller than `render-pdf-from-html` but still present since `waitUntil:'load'` resolves external resources.
