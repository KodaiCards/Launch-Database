## .claude/ configuration analysis

**`/home/user/Launch-Database/.claude/agents/project-tracking.md` is the ONLY config file in `.claude/`.** No `settings.json`, no `settings.local.json`, no `hooks/` directory, no `keybindings.json`, no `permissions` config. The harness defaults apply.

The single file defines a **project-tracking sub-agent contract** with these orchestrator-affecting rules:

1. **`expected_parent_sha` pre-flight check.** Every dispatch prompt to this agent type should include the expected base SHA. The agent runs `git merge-base --is-ancestor <expected_parent_sha> HEAD && echo OK || echo MISMATCH` and replies `PARENT_MISMATCH` (refusing all work) if the worktree base is stale. This protects against the silent worktree-branched-off-stale-ref bug.
2. **Worktree-aware path discipline.** Agent treats `pwd` as repo root (not hardcoded absolute paths) — important for `isolation: "worktree"` config which puts the agent at `<repo>/.claude/worktrees/agent-<id>/`. Note: CLAUDE.md §3 says `general-purpose` works fine and `claude` type fails worktree creation — this file confirms why (it assumes worktree harness exists).
3. **Hard rules:** no `--no-verify`, no `--force`, no `git reset --hard`, no destructive ops without explicit user approval, never push to main directly without authorization, no scope creep, default to commit+push with 4× retry exponential backoff (2/4/8/16s).
4. **Domain map:** which file owns what (admin SPA = `public/index.html`, project CRUD = `routes/projects.js`, billing = `routes/billing.js`/`routes/invoices.js`, etc.).
5. **Strict NOT-yours boundary:** splice subsystem (`public/splice.html`, `routes/splice.js`, `routes/_splice_validation.js`, `migrations/*splice*.sql`, `tests/splice*.test.js`) — separate roadmap in `SPLICE_BUILD_PLAN.md`.
6. **Conventions:** no scope creep, no comments unless WHY is non-obvious, no emojis (unless user asked), backwards-compat shims discouraged, additive migrations, frontend uses CSS variable tokens not hex codes for dark-mode compat.
7. **Report shape:** 1-2 sentence what-changed + SHA(s) + files-touched + ambiguity flags + out-of-scope flags, under 250 words.

**No hooks configured.** If we wanted SessionStart hooks, automated permissions, or pre/post-tool hooks, none exist today — that's a future improvement opportunity for the project. Orchestrator should NOT assume any harness-level automation is in place.

## CI workflow analysis

**Single job, three sequential steps, blocks PR merge AND direct-push-to-main (both trigger the job):**

| Step | Command | Failure mode |
|---|---|---|
| Backend smoke tests | `npm test` | Postgres-shaped test failures, schema bugs, missing required imports |
| Schema sync check | `npm run schema:sync && git diff --exit-code schema.sql` | Committed `schema.sql` out of sync with `migrations/*.sql` |
| Browser smoke tests | `npm run test:browser` (Playwright Chromium) | DOM regressions, missing IDs, UI broken |

**Pre-flight setup:** Node 20, Postgres 16 service container, env `TEST_DATABASE_URL`, `ADMIN_PASSWORD=test_admin_password_123` (must be ≥10 chars or auth.js refuses to seed admin), `JWT_SECRET=ci_smoke_test_jwt_secret_${{github.run_id}}` (per-run unique), `NODE_ENV=test` (suppresses prod-only auth behavior), `DEBIAN_FRONTEND=noninteractive` (prevents apt-get tzdata hang from 2026-05-04 incident). 30-min job timeout. Playwright browsers cached by version. Playwright report uploaded as artifact on failure (`retention-days: 7`).

**Triggers:** `pull_request:` (any PR) + `push: branches: [main]` (direct push to main). NOT triggered on push to feature branches outside of a PR — so any agent pushing to `claude/debug-previous-issues-MoN9D` does NOT trigger CI until merged to main OR opened as a PR. **Orchestrator must verify CI status on HEAD via `pull_request_read get_check_runs` or wait for merge before declaring CI-green** (CLAUDE.md §3 already locks this).
