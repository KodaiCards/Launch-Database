# Pedagogy Framework — "Accurate, and not boring"

> The evidence base every reviewer scores against (Axis B + C). Grounded in cognitive-science
> of learning (retrieval practice, cognitive load theory, Mayer's multimedia principles,
> worked-example effect, ARCS motivation). Use these as the checklist — cite the principle
> name in findings so the CEO can see the reasoning.

## The learning principles that actually move retention

1. **Retrieval practice (testing effect).** Pulling an answer from memory beats re-reading.
   Every lesson should make the learner *retrieve*, not just recognize. Low-stakes quizzes,
   "predict before reveal," fill-in-blank > passive flashcard flips. CHECK: does the lesson
   ask the learner to produce an answer before showing it?

2. **Spacing & interleaving.** Re-encounter terms across lessons; mix problem types. CHECK:
   are earlier-topic terms deliberately re-tested later (cumulative capstones), not just once?

3. **Worked examples → faded guidance.** Novices learn procedures faster from fully worked
   examples than from solving cold (worked-example effect). Then fade support as they gain
   skill (expertise-reversal: experts don't need the scaffold). CHECK: are calculations shown
   step-by-step with substitutions, then followed by a "you try" with less scaffolding?

4. **Concrete before abstract.** Lead with a real object/scenario, then generalize to the
   rule/formula. The T02.L01 "flashlight in a glass rod" → TIR is the model to emulate.

5. **Cognitive load management** (Sweller). Reduce *extraneous* load, manage *intrinsic*,
   promote *germane*:
   - **Segmenting**: chunk into small steps the learner controls (no 800-word monoliths).
   - **Signaling**: headers, bold key terms, "the one thing to remember" callouts.
   - **Coherence**: cut decorative filler that doesn't teach.
   - **Pre-training**: define every term/acronym before it's used in a procedure (the module
     already enforces `vocabulary_assumed` — good).
   - **Split-attention / contiguity**: put the explanation next to the diagram/number it
     explains, not paragraphs away.

6. **Dual coding.** Words + a visual representation beat words alone. Tables, diagrams,
   sliders, annotated figures. CHECK: is a dense numeric concept ever shown *only* as prose?

7. **Elaboration & self-explanation.** Ask "why does this work?" and "how does this connect
   to X you learned in T0?" Prompts that make the learner explain to themselves deepen encoding.

8. **Explanatory feedback.** Every quiz answer — right or wrong — needs a *why*, and good
   distractors should map to a specific misconception so the explanation can correct it.
   CHECK: are wrong choices plausible misderivations (the rubric already requires this)?

9. **Desirable difficulties.** Some struggle helps. Don't pre-chew everything; a well-placed
   "figure out which cable spec fails here" is better than handing over the answer.

## The engagement principles ("less boring") — ARCS + curiosity

- **Relevance / stakes up front.** Open with *why a tech in Macon cares* — money lost,
  a failed inspection, a safety incident, an exam question they'll see. Adults learn what
  they see a use for. Replace "This lesson covers NESC clearances" with the cost of getting
  it wrong.
- **Curiosity gap.** Pose the question before the answer ("Why does this $40k reel fail
  acceptance even though both fibers are G.652.D?"). Open loops pull readers forward.
- **Narrative & scenario.** A recurring field scenario or character (a staker, an inspector)
  carrying through a topic beats disconnected facts. Branching scenarios already exist — use
  them more.
- **Active > passive.** Prefer "drag these in install order," "pick the right armor for this
  route," "find the make-ready violation" over read-and-nod. The 7 primitives
  (Quiz, WorkedExample, BranchingScenario, Sortable, SliderExploration, SideBySide,
  TimelineSequence) are the tools — a boring lesson is usually one that under-uses them.
- **Confidence & success.** Early wins, then ramp difficulty. Show progress.
- **Voice.** Plain, direct, field-credible — not textbook-stiff, not gimmicky. Carter's bar:
  streamlined, concrete, no fluff.

## Concrete "de-boring" moves a reviewer can recommend

| Symptom | Fix |
|---|---|
| Wall of text / 3+ paragraphs before any interaction | Segment; insert a predict-then-reveal or a 1-question retrieval check |
| Several reference tables in a row | Convert one to a SliderExploration or Sortable; keep the rest as reference |
| Formula stated then used | Add a WorkedExample with substitutions shown, then a faded "you try" |
| Dry standards recitation | Frame as "what fails inspection if you ignore this" + a BranchingScenario |
| Definition list with no hook | Add a 1–2 sentence field-stakes opener (money/safety/exam) |
| Quiz with thin explanations | Map each distractor to a named misconception; explain the why |
| Term reused, never re-tested | Add it to a later cumulative capstone (spacing) |

## What "good" already looks like here (preserve, don't rewrite)

T02.L01 is a strong template: plain-English analogy → acronym table → core/cladding concrete
model → flashcards → working-tier physics with shown math → quiz with explanatory feedback,
tiered foundations/working/advanced. When a lesson is weak, push it toward this shape rather
than inventing a new one. Consistency across 254 lessons is itself a learning aid.
